# AI Coding 工程化：个人项目的组件边界

核验日期：2026-07-30  
证据口径：只使用官方文档、协议规范和源码；以下是产品判断，不代表已经完成实现或真实运行验证。

> **Decision（2026-08-01）：** `Delivery Evidence Plugin` 是较早的候选产品形态，
> 已被以 Symphony Runtime 为核心的 Workbench 定位取代。本文保留的价值是
> Evidence、Harness、MCP 和 Phoenix 的取舍原则，不再代表项目主干。当前决定见
> [`product-boundary.md`](../design-docs/product-boundary.md)。

## 结论

个人开发者最值得做的不是“通用多 Agent 平台”，而是一个 **repo-bound AI coding delivery evidence plugin**：

> 围绕一次 `Task Episode`，采集 Codex Hook 事件，读取当前仓库原生测试/构建结果，用确定性规则形成可回放证据包；网页只展示运行投影，MCP 只提供只读查询。

它能直接展示招聘需要的 harness、MCP、工程化、可观测与安全边界，同时一周内仍有完整闭环。LangGraph、Phoenix、Pi 和多 Agent 都不是首周必需项，只有出现下表中的真实需求才加入。

## 组件分层与规模触发条件

| 层 / 组件 | 个人项目当前价值 | 何时才值得加入或扩展 | 明确边界 |
|---|---|---|---|
| 项目原生验证 | 最高：复用仓库已有 test、lint、typecheck、build，证明改动是否通过 | 始终需要；按仓库事实选择最小验证集 | 不用 AI 自评替代测试结果 |
| Harness 证据模型 | 最高：用 `Task Episode`、证据状态和运行事件组织一次交付 | 有多次可比较 episode 后再做趋势分析 | Better Harness 是外层审计模型，不是实时 runtime |
| Codex Plugin + Hooks | 高：把 Skill、Hook、MCP 配置打包；Hook 提供生命周期事件 | 多仓库共用时再做配置模板和分发 | Hook 覆盖并不完整，是 guardrail/采集点，不是权限隔离边界 |
| 本地 JSONL + 证据包 | 高：可回放、可审计、便于 Demo | 数据量或多人并发出现后再换数据库 | 只记录脱敏结构化事件，不保存 raw thinking、凭证或无界输出 |
| SSE 实时页面 | 高：将本地事件投影成 timeline | 只有多用户、远程访问时才考虑 WebSocket、鉴权与部署 | 实时流来自本地服务，不来自 MCP |
| MCP Tools | 中高：让 Codex/其他 Host 查询 episode 与 findings | 至少有第二个 Host 或稳定 CLI 服务时价值更大 | 首周只读；显式传 `runId`，不能把 MCP 当工作流存储或事件总线 |
| MCP Resources | 低：适合让 Host 浏览 URI 化证据包 | 证据 artifact 已稳定、Host 的 Resources 体验已验证时 | Resources 是应用驱动上下文，不是动作接口 |
| MCP Prompts | 低：适合用户主动选择审查模板 | 多套稳定模板且 Host 确认支持时 | Prompts 是用户控制模板，不是后台编排 |
| LangGraph | 首周低：已有 Codex runtime 时会形成第二套执行状态 | 真的需要跨重启恢复、持久化 `thread_id`、暂停后人工恢复时 | interrupt 恢复会从节点开头重跑，副作用必须幂等 |
| Agent 编排 | 首周低：一个采集器加确定性检查器已足够 | 两个角色有独立上下文、独立证据，并能量化提升时 | “角色多”不是价值；单 Agent + 工具通常更简单 |
| Phoenix | 首周低：自建 timeline 已覆盖核心展示 | 反复排查 LLM/tool span、延迟和 token，且手写日志已不足时 | 只选一套观测后端；Phoenix MCP 也不是实时事件源 |
| Langfuse | 首周低：与 Phoenix 在 tracing/evals 上重叠 | 需要数据集实验、在线评分，或提示词由非开发者独立发布时 | 单人提示词先放 Git；不要与 Phoenix 同时接入 |
| Pi JSON / RPC | 首周低：当前目标是观察 Codex，不需再启动第二个 agent runtime | 需要可控的开放 runner、steer/abort 或跨 harness 适配时 | JSON 适合单向事件；RPC 适合双向控制；Pi 无内置 MCP 和 OS sandbox |

## 首选一周项目：Delivery Evidence Plugin

### 用户故事

开发者让 Codex 修改一个真实仓库；插件实时显示这次 episode 的阶段、工具调用和验证结果，并生成一个“哪些事实已证明、哪些仍未观察”的证据包，供 Codex 通过 MCP 只读查询。

### 最小结构

```text
Codex Hook
  -> 脱敏 RunEvent JSONL
  -> Episode projector
  -> repo 原生 test/lint/build
  -> deterministic evidence rules
  -> evidence.json + report.md
                    ├─ SSE -> 本地 timeline
                    └─ MCP -> list_runs/get_run/get_findings
```

Codex 插件只打包四样东西：一个使用 Skill、Hook 配置、本地 evidence service、`.mcp.json`。MCP Tool 不负责采集；Hook 不负责判定业务成功；页面不成为新的事实源。

### 一周完成定义

1. 在一个带失败/成功 fixture 的真实小仓库中跑通一次 episode。
2. Hook 事件经字段 allowlist 和长度限制后追加为 JSONL；未覆盖事件显示 `Not observed`。
3. 至少执行两个仓库原生命令，并保存命令、退出码、时间和报告路径。
4. 确定性规则输出 `Present / Wired / Exercised / Outcome-supported / Missing / Unobserved`。
5. 浏览器实时显示 session、turn、tool、verification、finding 五类投影；刷新后可从 JSONL 重放。
6. MCP 仅暴露 `list_runs`、`get_run`、`get_findings`，返回结构化内容并要求显式 `runId`。
7. `report.md` 明确区分：观察事实、规则推断、人工确认、`Not verified`。
8. README 演示一个真实失败如何被定位、修复、重新验证，不宣称生产级、多用户或通用质量评分。

### 首周明确不做

- 不启动 Pi worker，不做 parallel/chain subagents。
- 不接 LangGraph；没有跨重启人工审批状态机，就不为关键词增加第二套 runtime。
- 不接 Phoenix 或 Langfuse；先证明现有事件与证据模型能回答一个真实问题。
- 不解析不稳定 transcript，不采集 raw reasoning，不上传私有代码。
- 不做云部署、账号系统、组织级趋势面板或自定义综合分数。

## 后续扩展只按问题触发

- **要恢复一次长审查并在人批准后继续**：加入 LangGraph SQLite checkpointer、同一 `thread_id` 与 interrupt；先验证重放幂等。
- **要定位模型、检索、工具 span 的成本/延迟**：只接 Phoenix，以 OpenTelemetry/OpenInference 观测；多人/高可用后再迁 PostgreSQL。
- **要独立控制 agent、steer/abort 或比较 Codex 与另一 harness**：加 Pi RPC adapter，并映射到同一个 `RunEvent`，不另建事件真相。
- **要让非开发者独立发布 prompt 或跑数据集实验**：再评估 Langfuse；否则 prompt 与 evaluator 保持项目内版本控制。
- **要证明多 Agent**：先定义两个可独立验收的任务和基线；没有可量化收益就维持单 Agent。

## 两个反例 / 备选

1. **反例：全家桶 AI DevOps 平台。** LangGraph + Pi 多 Agent + MCP Resources/Prompts + Phoenix + Langfuse + 自建 dashboard 同时出现，会产生重复执行状态、重复 traces/evals 和多个事实源；一周只能展示接线，不能展示交付能力。
2. **更窄备选：Pi Episode Replay CLI。** `pi --mode json/rpc → JSONL → replay → evidence summary`，不做 Web、MCP、LangGraph。它更容易完成并能学习事件协议，但对“Codex 插件 + repo delivery evidence”的岗位展示覆盖更窄。
