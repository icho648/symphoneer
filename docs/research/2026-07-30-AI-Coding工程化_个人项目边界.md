## 组件分层与规模触发条件

| 层 / 组件 | 个人项目当前价值 | 何时才值得加入或扩展 | 明确边界 |
|---|---|---|---|
| 项目原生验证 | 最高：复用仓库已有 test/lint/typecheck/build | 始终需要 | 不用 AI 自评替代测试结果 |
| Harness 证据模型 | 高：组织一次交付的证据状态 | 有多次可比较运行后再做趋势 | 外层审计模型，不是实时 runtime |
| Codex Plugin + Hooks | 高：生命周期事件与 guardrail | 多仓库共用时再做模板分发 | Hook 覆盖不完整，不是权限隔离 |
| 本地 JSONL + 证据包 | 高：可回放、可审计 | 数据量/多人并发后再换数据库 | 只记脱敏结构化事件 |
| SSE 实时页面 | 高：投影 timeline | 多用户/远程访问时才扩展 | 实时流来自本地服务，不来自 MCP |
| MCP Tools | 中高：查询 run / findings | 至少有第二个 Host 时价值更大 | 不能当工作流存储或事件总线 |
| MCP Resources / Prompts | 低 | artifact 与 Host 体验稳定后再加 | Resources 非动作接口；Prompts 非后台编排 |
| LangGraph | 首周低 | 真需要跨重启恢复、interrupt 人工恢复时 | 中断恢复从节点开头重跑，副作用必须幂等 |
| 多 Agent | 首周低 | 两角色有独立上下文、独立证据且可量化提升时 | “角色多”不是价值 |
| Phoenix / Langfuse | 首周低 | 手写日志无法回答 span/成本问题，或需要数据集实验时 | 只选一套观测；不要双接 |
| Pi JSON / RPC | 首周低 | 需要开放 runner、steer/abort 或跨 harness 时 | JSON=单向事件；RPC=双向控制；Pi 无内置 MCP/sandbox |

## 两个反例

1. **全家桶平台：** LangGraph + Pi 多 Agent + MCP Resources/Prompts + Phoenix + Langfuse + 自建 dashboard 同时上，会产生重复执行状态与多个事实源。
2. **过窄备选：** 纯 Pi Episode Replay CLI 易完成，但对 Codex 交付工作台覆盖更窄。
